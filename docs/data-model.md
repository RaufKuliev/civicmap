# Версионирование данных CIVIC MAP

## Основные правила

- Публичные JSON-файлы являются снимками на дату, а не «текущей истиной» без даты.
- Схема кандидата v2 сохраняет совместимые плоские поля для интерфейса и добавляет `sources`, `facts` и `status_history`.
- Каждый изменяемый факт содержит `as_of` и хотя бы один `source_id`.
- События статуса упорядочены по `effective_on`, не перезаписывают прошлые события и ссылаются на сохранённые источники.
- Партийный список подтверждает только выдвижение или включение в заверенный список. Он не подтверждает регистрацию.
- Решения комиссий хранятся в `decision` с номером, датой и названием комиссии; обязательность решения для авторитетных конечных статусов усиливается в official-source pipeline.

## Совместимость

`candidateInputSchema` принимает текущую схему v1 и детерминированно преобразует её в v2 в памяти. Исходные файлы при чтении не меняются. Миграция создаёт один источник, пять датированных фактов и одно историческое событие, сохраняя прежние публичные поля.

## Переходы статусов

Разрешённые переходы задаются в `allowedStatusTransitions`. Терминальные результаты выборов не меняются автоматически. `status_pending_verification` используется как явное состояние неопределённости и может быть заменено только новым датированным источником.

## Снимки и diff

`candidateSnapshotSchema` содержит идентификатор снимка, предшественника, дату, источники и контрольные количества. Команда `pnpm data:diff -- --before <json> --after <json>` печатает детерминированный JSON со списками `added`, `removed` и `changed`, отсортированными по ID кандидата.
